# Решения и допущения

- Одна строительная компания, две взаимоисключающие роли. Несколько постановщиков имеют одинаковые права на все активные объекты и задачи.
- У задачи всегда один исполнитель с ролью `executor`. Назначать постановщика исполнителем нельзя.
- Название и адрес объекта, название задачи и исполнитель обязательны. Описание задачи необязательно. База ограничивает название 200, адрес 500, описание и комментарий 10000 символами.
- Редактирование полей, перемещение на другой объект и переназначение доступны постановщикам в любом статусе. Они не меняют статус, автора, дату создания или историю. Принятые задачи повторно не открываются.
- При переназначении прежний исполнитель теряет доступ ко всей задаче и её истории, новый получает историю целиком.
- Удаление мягкое, через `deleted_at`. Удаление объекта одной транзакцией скрывает его задачи. История физически сохраняется, но не показывается для удалённой задачи. Восстановление в интерфейсе не реализовано.
- История содержит также первоначальное событие «создана → новая». Имена автора и участников сохраняются как снимки на момент события.
- Редактирование обычных полей не включается в историю статусов: по ТЗ требуется именно история смены статуса.
- Пользователей и роли подготавливает администратор через Supabase или локальный скрипт. Формы регистрации и управления пользователями в CRM отсутствуют.
- Обновление данных выполняется после действий, возвращения на вкладку и повторного запроса. Постоянное соединение Realtime не требуется для этого объёма.
- На VPS обнаружен работающий Nginx. Он обслуживает домен и HTTPS, а отдельный контейнер Caddy отдаёт приложение на `127.0.0.1:18084`. Это позволяет использовать существующую инфраструктуру сервера.
- Для сдачи выбран текст для руководителя вместо видео. Доступы передаются отдельно от открытого репозитория.

# Развёртывание на VPS

Приложение собирается из конкретного коммита Git и запускается отдельным проектом Docker Compose `mini-crm`. В контейнере Caddy отдаёт готовые файлы React на порту `8080`. Снаружи контейнер доступен только как `127.0.0.1:18084`; домен `work-search.ru` обслуживает уже установленный на сервере Nginx. HTTPS-сертификат получает существующий Certbot.

## Подготовка

На рабочем компьютере нужны Git, Python 3 и Paramiko:

```powershell
python -m pip install paramiko
```

В корне проекта находятся локальные файлы, исключённые из Git:

- `.env`: `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` и, только для подготовки пользователей и проверок, `SUPABASE_SECRET_KEY`. Для сборки также поддерживаются `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`.
- `ssh.txt`: в первой строке команда `ssh user@server` с необязательными `-p`, `-l`, `-i`; во второй — пароль, если используется вход по паролю. Значения доступов не публикуются.
- `.deploy/`: архивы исходников и закреплённый ключ SSH-сервера.

На VPS нужны Docker с Compose, Nginx, Certbot, `curl`, `tar` и права на Docker, `/opt/mini-crm` и конфигурацию Nginx. DNS домена должен указывать на VPS, а порты 80/443 — принимать внешние подключения. Существующий Certbot должен иметь зарегистрированную учётную запись ACME.

## Публикация

Сначала выполнить сборку и проверки приложения, затем закоммитить исходники. Публикация при незакоммиченных изменениях остановится: сервер получает именно `git archive HEAD`.

```powershell
python scripts/deploy.py inspect
python scripts/deploy.py publish
python scripts/deploy.py tls
python scripts/deploy.py status
```

При первом соединении скрипт сохраняет отпечаток ключа сервера в `.deploy/ssh-known-hosts`; следующие соединения проверяют этот ключ. Известный заранее отпечаток можно закрепить явно:

```powershell
python scripts/deploy.py inspect --fingerprint "SHA256:EXPECTED_FINGERPRINT"
```

`publish` загружает исходники в `/opt/mini-crm/releases/<commit>`, собирает образ `mini-crm:<commit>`, запускает контейнер и проверяет `/healthz`. В удалённый `.env` попадают **только публичные** параметры Supabase и идентификатор релиза. Секретный ключ, пароли и `ssh.txt` не включаются в архив или образ. Архив дополнительно проверяется на наличие локальных секретных файлов и настроенных секретных значений.

Для домена создаётся отдельный файл `/etc/nginx/sites-available/mini-crm-work-search.ru.conf` и ссылка в `sites-enabled`. Изменения этого файла сохраняются в резервной копии; перед каждой перезагрузкой выполняется `nginx -t`. Чужой виртуальный хост с таким же доменом не перезаписывается. После получения сертификата HTTP перенаправляется на HTTPS, кроме пути ACME-проверки. При последующих публикациях HTTPS сохраняется.

Текущий релиз указан ссылкой `/opt/mini-crm/current`, предыдущий — в `/opt/mini-crm/deployment-state.json`. Образы и предыдущие релизы автоматически не удаляются. Если новый контейнер или конфигурация Nginx не проходят проверку, скрипт восстанавливает предыдущий контейнер и собственную конфигурацию.

## Откат и обслуживание

```powershell
# Предыдущий сохранённый релиз:
python scripts/deploy.py rollback

# Конкретный сохранённый релиз:
python scripts/deploy.py rollback --release FULL_40_CHARACTER_COMMIT_SHA

# Проверка после отката:
python scripts/deploy.py status
```

Откат переключает только приложение. Миграции Supabase и пользовательские данные сохраняются; для несовместимого изменения схемы требуется отдельная миграция. Перед выпуском таких изменений необходимо сохранить совместимость с предыдущим приложением.

На сервере логи приложения доступны через `docker compose -p mini-crm -f /opt/mini-crm/current/compose.yaml logs --tail 100 crm`. Выпуск сертификата использует Webroot `/var/www/letsencrypt`; дальнейшее обновление выполняет существующий таймер Certbot. Команда `tls` устанавливает исполняемый hook `/etc/letsencrypt/renewal-hooks/deploy/mini-crm-reload-nginx`: после обновления сертификата он проверяет наличие домена CRM в `RENEWED_DOMAINS`, выполняет `nginx -t` и только затем перечитывает конфигурацию Nginx. Обновления остальных сертификатов этот hook пропускает. Перед заменой собственного hook сохраняется неисполняемая резервная копия; чужой файл по тому же пути скрипт не перезаписывает.

Скрипт управляет только проектом Compose `mini-crm`, его каталогом и отдельным виртуальным хостом. База и вход пользователей остаются в облачном Supabase.
